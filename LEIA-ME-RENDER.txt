MARACANÃS V24 — LEITURA DE PDF E OCR AUTOMÁTICO

ATUALIZAR O SERVIÇO EXISTENTE
1. Extraia o ZIP. Envie o CONTEÚDO da pasta Central_V24_Render para a mesma raiz do projeto no GitHub, substituindo os arquivos correspondentes. package.json, package-lock.json, render.yaml, src, server e shared precisam ser atualizados juntos. Não basta trocar App.jsx.
2. Use o mesmo repositório, serviço Render e disco persistente /var/data. Não crie outro Blueprint para esta atualização. Não envie node_modules, dist, data, bancos, .env ou chaves.
3. Mantenha o build: npm ci --include=dev && npm run build
   Mantenha o start: npm start
   Root Directory: pasta que contém package.json.
4. Após o commit, aguarde o deploy automático, caso esteja habilitado; caso contrário, faça deploy do commit mais recente no serviço existente.
5. Entre com a mesma conta. Abra a licitação que apresentou erro e clique em "Atualizar documentos e gerar análise oficial". O erro anterior não é reprocessado sozinho.
6. Confira o relatório "Conferir páginas e métodos de leitura" e os oito blocos do resumo.

Esta atualização não exige outra chave para OCR. O modelo português é instalado via npm e utilizado localmente no servidor, sem CDN durante a leitura. O resumo por IA continua exigindo OPENAI_API_KEY e saldo na API. A assinatura do ChatGPT não paga essa API.

O QUE FOI CORRIGIDO
- Página renderizada inteiramente branca não interrompe o resumo.
- Páginas sem texto suficiente e páginas com pouco texto e imagens passam por OCR.
- Leitura nativa, OCR, página branca e página pendente são identificados por documento e página.
- Páginas ilegíveis continuam pendentes. Havendo outras páginas legíveis, gera-se um resumo explicitamente parcial; não se conclui que uma exigência está ausente no edital completo.
- Se nenhuma página puder ser lida, não há resumo novo; relatório da tentativa é salvo e o resumo anterior é preservado e identificado.
- OCR de baixa confiança não vira informação preenchida. Texto reconhecido ainda exige conferência, especialmente números e tabelas; confiança OCR não comprova exatidão.
- A recomendação "Recomendada" fica bloqueada enquanto houver páginas pendentes. Parecer condicionado continua disponível.
- Falhas nos detalhes da busca aparecem com motivo e botão para repetir somente os resultados com falha.
- Filtros continuam dentro de "Mostrar todos os filtros". São filtros do acervo carregado; campos sem dados disponíveis permanecem indisponíveis, sem dados inventados.

LIMITES E REVISÃO
Até 12 PDFs por análise, 20 MB e 150 páginas por PDF, 240 mil caracteres no conjunto.
Até 20 páginas processadas por OCR em uma análise. Limite por página: 90 segundos. Limites atingidos aparecem como pendências; selecione menos documentos e repita ou confira/preencha os campos manualmente.
O sistema processa uma análise de cada vez no servidor. OCR e sete blocos de resumo podem levar vários minutos. Na análise automática PNCP, fechar a ficha não interrompe o trabalho.
PDF criptografado, corrompido, imagem muito ruim, tabelas complexas e imagem misturada com texto abundante podem requerer revisão manual. Leitura concluída significa páginas processadas, não garantia de extração integral de cada elemento visual.
Sete chamadas de IA extraem os blocos documentais; dados da empresa, cotações, disponibilidade e parecer estratégico dependem da equipe. Cada chamada recebe o texto selecionado. store:false é enviado; isso não promete retenção zero do provedor.
Os campos precisam de trecho literal, documento e página. Números sem suporte são descartados. Essa validação não garante interpretação correta; confira o original.
O PNCP fornece situação, dados e documentos publicados. Pendências na coleta são exibidas. Não se promete encontrar editais de todas as 17 fontes; as integrações e limitações existentes são preservadas.

DADOS E CONTAS
Contas, licitações, PDFs, complementos, comentários, relatórios de leitura e auditoria ficam no servidor, no disco persistente. Não se usa localStorage, sessionStorage ou IndexedDB. A sessão usa cookie HttpOnly.
Preservar /var/data/auth.sqlite e o mesmo disco mantém as contas e os registros já existentes. Não execute criar-admin para recriar uma conta que já funciona.
Para uma instalação nova, execute npm run criar-admin no Shell do serviço. Não há senha padrão. Senha mínima: 12 caracteres. Funcionários são criados em Administração, com permissões explícitas.
Conflitos de edição retornam erro 409: recarregue a ficha antes de salvar novamente. A auditoria registra o autor das ações no sistema e alterações com antes/depois, não atividades fora do site.
Backups diários locais incluem banco e PDFs; os dez últimos são mantidos no mesmo disco. Uma cópia no mesmo disco não substitui backup externo.

VALIDAÇÃO DESTA VERSÃO
npm test: inclui leitura real de PDF com texto, página branca e OCR português offline, pendências, limite/timeout, resumo parcial com API simulada, permissões e preservação de resumo anterior.
npm run build: valida o frontend para produção.
Não houve chamada real à OpenAI nem deploy na conta Render nesta validação. Depois de publicar, reprocessar um edital real confirma chave, saldo, conectividade e consumo de memória do seu serviço.
